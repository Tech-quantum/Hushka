# 📱 پروژه Hushka (هوشکا) — سند انتقال و ادامه توسعه

## 🎯 اطلاعات کلی پروژه
- **نام پروژه**: هوشکا (Hushka)
- **پلتفرم**: اندروید (Kotlin + Jetpack Compose)
- **پکیج اصلی**: `com.techquantum.hushka`
- **ریپوی گیت‌هاب**: https://github.com/Tech-quantum/Hushka
- **ساختار فایل‌ها**: تخت (Flat) و همه در یک پکیج (`com.techquantum.hushka`)؛ تنها استثنا زیرپکیج `audio/` است (`audio/SilenceDetector.kt`).
- **وضعیت فعلی**: شاخه‌ی کاری `main` است. تغییرات از طریق شاخه‌های `feature/*` و Pull Request روی GitHub انجام می‌شود (شاخه‌ی قدیمی `dev` بازنشسته شده است).

## 🛠 تکنولوژی‌ها
- Kotlin 1.9.24, Compose BOM 2024.09.03, Material 3
- Room Database (نسخه ۸)
- Retrofit, OkHttp (برای ارتباط با APIها)
- DataStore (برای تنظیمات)
- Coil (برای نمایش تصاویر)
- Vosk (برای تشخیص گفتار آفلاین) — مدل‌های ZIP با **Git-LFS** نگه‌داری می‌شوند

## ✅ قابلیت‌های پیاده‌سازی شده
1. **چت با ۴ سرویس AI**: Gemini, Groq, OpenAI, DeepSeek
   - دارای قابلیت **استریم پاسخ (Typewriter)** (کلمه به کلمه تایپ می‌شود).
2. **تولید تصویر با AI**: با استفاده از سرویس رایگان **Pollinations.ai** (بدون نیاز به کلید API).
   - دیالوگ یکپارچه `AddDialog` با ۲ تب: «پرامپت جدید» و «تولید تصویر».
3. **میکروفون ترکیبی**: 
   - آنلاین با **Groq Whisper** (کلید API رایگان) — مسیر پیش‌فرض.
   - آنلاین با **Google Gemini** (`gemini-3.5-transcribe`) — مسیر دوم، پشتیبانی رسمی فارسی (`fa-IR`).
   - آفلاین با Vosk (مدل‌های زیپ‌شده فارسی، انگلیسی، عربی، ترکی در پوشه assets).
   - انتخاب موتور در `MainActivity.startVoiceSearch()` و بر پایه‌ی کلید «تشخیص گفتار» انجام می‌شود.
   - ضبط آنلاین: `AudioRecord` (PCM 16-bit mono 16kHz) با خروجی `voice_input.wav` + تشخیص سکوت تطبیقی (`audio/SilenceDetector.kt`).
   - فالبک خودکار: اگر Groq شکست بخورد، همان فایل WAV بدون ضبط مجدد به Gemini ارسال می‌شود.
4. **متغیرگذاری هوشمند (Smart Variables)**: تشخیص خودکار `[VARIABLE]` و باز کردن فرم پر کردن مقادیر با ترجمه ۴ زبانه.
5. **دسته‌بندی نقش‌ها (Roles)**: ۴۰+ نقش تخصصی (عمومی و روانشناسی) با دیالوگ انتخاب مدرن.
6. **استریک روزانه (Daily Streak)**: شمارش روزهای متوالی استفاده از اپ (با DataStore).
   - نمایش نشانگر (🔥) در نوار بالای صفحه اصلی: **سمت راست، روبروی لوگو** (لوگو چپ، عنوان وسط‌چین).
   - شعله‌ی **متحرک** با ضربان، لرزش و هاله‌ی درخشان (`AnimatedStreakBadge`).
7. **UI/UX مدرن**: Splash Screen، انیمیشن‌ها، Swipe-to-Delete، تم AMOLED (مشکی مطلق)، ۴ زبان زنده دنیا.
8. **آمار پیشرفته**: نمودارهای دایره‌ای و ستونی با Compose Canvas.
9. **ترجمه خودکار عنوان‌ها**: با API MyMemory.

## ⚠️ قوانین بسیار مهم (حتماً رعایت شود)
1. **قانون شاخه‌ی کاری**: هرگز مستقیم روی `main` کد نزنید. برای هر تغییر یک شاخه‌ی تازه **از `origin/main`** بسازید (مثل `feature/...`، `fix/...`، `ui/...`، `docs/...`)، بعد Pull Request بزنید و پس از سبز شدن CI مرج کنید.
   - نکته‌ی مهم: شاخه را از `origin/main` بسازید، نه از تاریخچه‌ی کامل محلی — وگرنه پوش به‌خاطر حجم مدل‌های صوتی سنگین می‌شود.
2. **قانون مستندات**: پس از هر **تغییر ساختاری، رفع اشکال یا بهینه‌سازی فنی** فقط این ۳ فایل باید آپدیت شوند: `HISTORY.md`، `STATUS.txt` و `Handoff Document.txt`. فقط وقتی **قابلیت/توانایی جدیدی** به کاربر اضافه شد، `README.md` هم به‌روزرسانی می‌شود. (برای نوشتن در فایل‌ها همیشه از اسکریپت پایتون استفاده کنید تا ترمینال خراب نشود — قاعده‌ی ۳).
3. **مشکل هردوک (Heredoc)**: در Termux، هرگز متن‌های طولانی مارک‌داون را مستقیم با `cat << EOF` ننویسید (باعث به هم ریختگی و خطای سینتکس می‌شود). همیشه از **اسکریپت پایتون** (`python3 << 'PYEOF'`) برای نوشتن در فایل‌ها استفاده کنید.
4. **مشکل `LocalContext` در Compose**: هرگز `LocalContext.current` را داخل بلاک `LaunchedEffect` قرار ندهید. آن را بیرون تعریف کرده و پاس بدهید.
5. **تغییرات با Regex**: در اسکریپت‌های پایتون، همیشه الگوها را با دقت چک کنید تا کدهای دیگر (مثل آکولادها یا ایمپورت‌ها) پاک نشوند.
